# 折间 ORI

一张纸的三维折纸工作室。折法不是一份固定成品，而是一组可以反复重解的尺寸参数：
拖动纸张宽高、折痕距边缘的比例或目标开口角，整套纸面、折轴与步骤都会重新求解。

## 本地启动

```sh
npm install
npm run dev
```

## 检查与构建

```sh
npm run typecheck
npm run build
```

## Docker

```sh
docker compose up --build
```

访问 http://localhost:18116。

## 参数化折法

右侧「尺寸参数」面板中的每个参数都会触发一次完整的重新求解，而不是把成品整体缩放：

- **纸张宽高**（毫米）：纸张以左下角为公共转轴，折痕是按纸边比例落笔的射线，
  因此改变宽高会改变各道折痕的实际角度，必须重新求解纸面分区与折叠姿态。
- **折痕位置**：每条折痕的落点用「距所在纸边起始角的比例」表示。
  比例可以在合法区间内交叉，交叉后折痕的执行顺序由几何重新判定。
- **目标开口角**：成品最外侧纸面相对平展纸面的开口角。求解器只在「从平展开始单调打开」
  的第一段上找解；目标超出可达范围时会直接报告 `可达 0–N°`，不会裁剪折角凑出一个假姿态。
- **山/谷方向**：翻转某道折痕的方向属于折法意图的一部分，同样在确认时整体提交。

### 预览、提交与取消

拖动只修改草稿，画布用半透明虚线纸面叠加显示新参数下的形态，并与当前实线纸面共用取景比例，
方便直接对照形状变化。确认时纸面、折轴、最终角度、步骤、标记点和迁移报告作为一个整体写入；
任何校验失败都不会写入文档，不会出现只更新一半的作品。取消会丢弃草稿，完整恢复之前的纸张与折法。

### 标记点与步骤迁移

- 纸上标记点以纸张归一化坐标保存，参数变化时它们不移动，只是随所在纸面一起运动。
  因此「原来的标记点是否还落在同一片纸面区域」可以直接看出来，并作为步骤能否迁移的判据。
- 比例交叉导致折痕顺序变化时，可迁移的步骤会注明顺序变化并排到新位置；
  失去对应区域的步骤（纸面被挤成窄条、折角归零、标记点滑出原区域）会被收回并附上原因。
- 被收回的步骤完整保存在 `retired` 中，把参数调回原值就会原样恢复，不会丢步骤。

## 结构

```
src/
  shared/           几何、向量与文档模型
    geometry.ts     按尺寸参数重建纸面分区与折轴
  features/
    paper/          纸型模板与预设
    scheme/         参数求解、标记点、预览/提交会话
      lib/resolve.ts  纸面 + 折叠姿态 + 步骤迁移的完整求解
      lib/marks.ts    材料坐标标记点及其归属判定
      model/session.ts 草稿、预览缓存、整体提交与取消
    fold/           姿态求解与手动微调
    sequence/       步骤播放与步骤保存
    observe/        视图、投影与导出
```
